# RegHive

Плагін Lister (WLX) для Total Commander, який читає **сирі, автономні файли
кущів реєстру Windows** — саме ті файли, які зазвичай не можна просто
відкрити, бо Windows тримає робочий реєстр заблокованим. Лише для читання;
RegHive ніколи не змінює відкритий файл.

Типовий сценарій: копія `NTUSER.DAT`, `SOFTWARE`, `SYSTEM` тощо з резервної
копії, старого диска або підключеного образу — файли, які інакше довелося б
спочатку підключати до робочого реєстру командою `reg load` лише для того,
щоб у них заглянути.

## Що вміє плагін

- Розпізнає та розбирає сирі файли кущів: `SYSTEM`, `SOFTWARE`, `SAM`,
  `SECURITY`, `DEFAULT`, `NTUSER.DAT`, `UsrClass.dat`, `*.hiv`
- Дерево розділів зліва, таблиця значень (Ім'я / Тип / Дані / Підказка)
  справа — клік по розділу показує його значення
- Декодує всі поширені типи значень: `REG_SZ`, `REG_EXPAND_SZ`,
  `REG_MULTI_SZ`, `REG_DWORD`, `REG_QWORD`; `REG_BINARY` показується як
  HEX-перегляд
- Показує час останньої зміни кожного розділу
- **Стовпець-підказка про переносимість**: позначає значення, які, ймовірно,
  не переживуть перенесення на інший комп'ютер/обліковий запис — посилання
  на SID, жорстко задані шляхи до дисків або шляхи зі змінними середовища
- Правий клік на значенні копіює його ім'я, дані, "ім'я = дані" або відкриває
  **повний HEX+ASCII-дамп** в окремому вікні (закривається клавішею Esc)
- **Пошук** (Ctrl+F у Lister) підключено до власного діалогу пошуку Total
  Commander — шукає за іменами розділів, іменами значень і вмістом
  рядкових значень; враховує "враховувати регістр"/"назад", завжди
  продовжує з поточної позиції курсора в дереві
- **Alt+F3** (наступний/попередній файл) використовує те саме вікно замість
  відкриття нового
- **Режим порівняння**: правий клік по дереву → "Порівняти з файлом..."
  порівнює два файли кущів. Розділи/значення позначаються як `[+]` (є лише
  у файлі B), `[-]` (відсутнє у файлі B), `[~]` (змінено десь нижче) або без
  позначки (ідентично)
- Інтерфейс доступний німецькою, англійською, російською та українською
  мовами; мова автоматично відповідає мові Total Commander (див. розділ
  «Мова»)

## Встановлення

Скопіюйте `RegHive.wlx64` (64-бітний Total Commander) та/або `RegHive.wlx`
(32-бітний), а також `reghive.lng` у папку плагінів TC, потім додайте
плагін через *Конфігурація → Налаштування → Плагіни → Lister-плагіни* (або
скористайтеся доданим `pluginst.inf`).

## Мова

Мова інтерфейсу автоматично відповідає мові Total Commander. Файл
`reghive.lng` (у тій самій папці, що й DLL) містить по одному розділу на
мову; RegHive використовує розділ, ім'я якого збігається з останньою
частиною імені поточного мовного файлу TC — `WCMD_DEU.LNG` вибирає
`[deu]`, `WCMD_RUS.LNG` — `[rus]`. Наявні розділи `[eng]`, `[deu]`,
`[rus]` та `[ukr]`. Якщо розділ, ключ або сам файл відсутній,
використовується англійська мова.

Щоб задати мову незалежно від TC, вкажіть її в `reghive.ini` (та сама
папка, що й DLL):

```ini
[Settings]
Language=uk
```

Допустимі значення: `auto` (за замовчуванням) або код мови, наприклад
`eng`, `deu`, `rus`, `ukr` (короткі форми `en`, `de`, `ru`, `uk` теж
працюють).

## Відомі обмеження

- Дуже великі кущі (зазвичай `SOFTWARE`/`SYSTEM` у довго використовуваних
  системах) можуть використовувати формат непрямих списків підрозділів
  (записи `ri`), який поки що не розбирається — уражені піддерева просто
  пропускаються, не викликаючи збою.
- Режим порівняння не розпізнає перейменовані розділи як "перейменовані" —
  перейменований розділ відображається як один видалений і один новий
  елемент.
- Пошук і HEX-перегляд недоступні в режимі порівняння.
- Свідомо лише для читання — функція редагування не планується.
